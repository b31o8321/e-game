# 知识神塔（Knowledge Tower）设计文档

**日期**：2026-05-03  
**状态**：已确认，待实现

---

## 一、产品定位

面向小学4–6年级学生的**学科 RPG 学习平台**，在家自学使用。以"搜打撤建"游戏循环驱动学习动力，第一个学科包为英语（4–6年级），架构支持后续扩展数学、语文等学科包。

---

## 二、技术栈

| 层次 | 技术 |
|------|------|
| 游戏引擎 | Godot 4 + GDScript |
| 发布平台 | macOS · Windows · Android |
| 认证 + 数据库 | Supabase（Auth + PostgreSQL） |
| 发音播放 | 音频文件随 ContentPack 打包（离线可用） |
| 口语跟读 | whisper.cpp + base 模型（~74MB）via GDExtension，三端统一，离线可用 |
| 离线支持 | ContentPack 本地缓存，进度联网同步 |

## 三、世界观与故事

### 3.1 背景

远古时代，世界所有知识储存于中心的**知识神塔**。一场"遗忘之灾"使神塔崩塌，知识碎片化为怪物和封印，散落各地，世界陷入愚昧黑暗。

主角是少数保有残存记忆的"觉醒者"，踏上找回知识、重建神塔的旅程。

### 3.2 目标结构

- **神塔**分为多翼，每翼对应一个学科
- 每翼分多层，每层对应一个年级的知识单元
- 解锁新翼/新层需通过对应的**里程碑大关**

### 3.3 首发内容

**英语翼**，覆盖4–6年级：词汇、语法、阅读、听力、口语。

## 四、核心游戏循环

### 4.1 总览

```
解谜解锁（学习）
    ↓
野外探索（复习 + 资源采集）
    ↓
战斗（应用知识）
    ↓
撤退报告 → 城市建设（升级 + 解锁）
    ↑_____________________________|
```

### 4.2 学习侧（输入）

**解谜解锁**：进入新知识单元前，用互动谜题体验该概念。
- 例：英语过去式 → 找散落动词碎片排进时间轴
- 例：英语词汇 → 拼图拼出单词的图画含义
- 谜题通关后，该知识点进入战斗题库，对应攻击类型解锁

**城市建设升级**：消耗野外资源，升级四座建筑，解锁新技能和更强攻击效果：
- 词汇图书馆 → 词汇攻击力 + 解锁新词汇技能
- 语法学院 → 语法攻击效果（如"沉默"怪物）
- 听力塔楼 → 听力题时限宽松 + 奖励倍率
- 口语广场 → 口语技能解锁

### 4.3 练习侧（输出）

**野外探索**：
- 地图上散落资源节点（英语结晶、语法矿石、故事书页等）
- 采集资源触发小题（1道多选题），答对才能拾取
- **题目从 SRS 复习队列中抽取**（优先历史错题），探索即复习
- 发现怪物可主动战斗或绕过

**战斗**：见第五节

**撤退报告**：每次远征结束（主动撤退/HP耗尽/通关）弹出统计：
- 本次答题数 / 正确率
- 分学科正确率柱状图
- 最常错知识点高亮（一键进入专项练习）
- 获得资源 / 装备 / 经验
- 连击峰值

## 五、战斗系统

### 5.1 基本流程

1. 玩家从可用攻击中**主动选择**一种（每种对应一个学科类型）
2. 弹出对应类型的多选题（4选1）
3. 答对 → 角色攻击动画，造成伤害，连击+1
4. 答错 → 角色受伤，连击清零，展示讲解+发音
5. HP耗尽 → 自动撤退，保留本次资源，触发撤退报告

### 5.2 怪物弱点

- 每只怪物有1–2个弱点学科类型，显示在HP条下方
- 命中弱点：×1.5 或 ×2 伤害
- 策略核心：观察弱点 → 选对应攻击 → 事半功倍

### 5.3 连击系统

| 连击数 | 效果 |
|--------|------|
| 3 连 | 强化效果触发（取决于BD） |
| 5 连 | 技能加成激活 |
| 10 连 | 大招可用 |
| 答错 | 连击清零 |

### 5.4 题目规范

- 全部多选题（4选1）
- 每题附**发音按钮**（英语单词/句子朗读）
- 答完后展开**讲解**（释义 + 例句）
- 答题有时限（取决于难度/技能）

## 六、双轨关卡结构

### 6.1 日常小关（Roguelike）

- 短平快，随机生成，资源/装备掉落
- 每次远征随机抽取技能，逐步构建当次 BD
- 死亡/撤退不惩罚，鼓励多次尝试

### 6.2 里程碑大关（Knowledge Gate）

- 解锁新地图区域 / 新剧情章节 / 新技能类型 / 新资源类型的前置条件
- 题目从该知识层级的**精选陷阱题/考点题池**中随机抽取（同等难度随机，非固定题目），每次挑战题目不同
- 普通敌人从该章节设计好的怪物池中轮转出现，有剧情逻辑
- 终点为章节 **Boss**（详见第六节Boss系统）
- 不调用 Roguelike 技能加成，纯考验知识
- 可反复挑战，通关后永久解锁
- 通关后触发剧情动画，强化成就感

### 6.3 敌方升级逻辑

- 地图怪物强度和题目难度绑定玩家当前"知识层级"
- 不通过里程碑大关，无法进入更高难度区域
- 同一区域可刷日常小关，但新内容必须解锁才出现

## 七、BD 技能系统（Roguelike）

### 7.1 技能类型

| 类型 | 说明 |
|------|------|
| 主动技能 | 战斗中释放，消耗能量 |
| 被动技能 | 持续生效，强化其他技能 |
| 协同效应 | 同时持有两个特定技能触发额外加成 |
| 传说技能 | Boss掉落，改变核心规则 |

### 7.2 四种 BD 方向

**燃爆流**（初始解锁）：快速连击 → 爆发伤害。连击加速、余烬持续伤害、超连击范围爆炸。

**铁壁流**（初始解锁）：高容错 → 稳定输出。错误护盾（不断连击）、回血、不屈（低HP反击）。

**元素流**（城市 Lv.5 解锁）：弱点克制 → 元素反应。攻击类型各对应元素，组合触发反应（如火+冰=融化×1.5）。

**召唤流**（词灵50只解锁）：词灵伙伴协同战斗。词灵数量越多越强，与故事收集系统深度绑定。

### 7.3 远征机制

- 出发前从技能池随机抽3选1
- 战斗胜利后从奖励中继续选技能
- 城市升级 → 技能池扩大，更好的协同可能性
- 永久解锁不随死亡消失，单次远征技能随远征结束重置

## 八、装备系统

| 槽位 | 效果方向 |
|------|---------|
| 武器 | 强化某类攻击伤害 |
| 护甲 | 答错时减少HP损失 |
| 饰品 | 特殊机制（如连击护符：答错一次不清零） |
| 坐骑 | 探索速度 + 资源采集范围 |

**获取途径**：野外探索掉落、Boss战奖励、城市锻造（消耗材料制作）

装备的名称、外观、描述文本由 ContentPack 定义，不同学科主题各异。

## 九、专项练习场

城市内独立建筑"训练道场"：
- 根据 SRS 数据生成专项关卡，专攻薄弱知识点
- 无探索、无资源压力，纯刷题
- 通关获得少量资源奖励，不影响主线进度
- 撤退报告里的"一键进入专项练习"直接跳转到对应题组

## 十、进度持久化

- **本地缓存**：ContentPack 数据缓存本机，离线可玩
- **云端同步**：账号登录后，进度（城市、装备、词灵、知识解锁状态）同步至 Supabase
- **SRS 数据**：每道题的答对/答错历史持久化，用于复习队列优先级

## 十一、家长看板

独立 Web 页面（非游戏内），家长账号登录后查看：
- 本周学习时长 / 活跃天数
- 各学科知识点掌握进度
- 薄弱点高亮
- 近期战斗表现（连击、正确率趋势）

## 十二、ContentPack 插件架构

每个学科包是独立插件，包含以下四个模块：

```
ContentPack/
├── knowledge/       # 题库（题目、讲解、发音、难度标签）
├── puzzles/         # 解谜场景（解锁新概念用）
├── skills/          # 攻击类型定义、BD技能池、技能描述文本
├── equipment/       # 装备表（名称、属性、主题描述、图标引用）
└── buildings/       # 城市建筑定义（名称、升级效果、对应攻击类型）
```

游戏引擎通过统一接口加载 ContentPack，不硬编码任何学科逻辑。怪物弱点、建筑类型、攻击类型均从当前激活的 ContentPack 读取。

**首发包**：`english-pack-grade4-6`（词汇/语法/阅读/听力/口语，4–6年级）

**扩展包预留**：`math-pack`、`chinese-pack`（架构兼容，内容待开发）

## 十三、Boss 系统架构

### 13.1 设计原则

大关通用流程由引擎统一处理（入场动画、HP条、胜负判定、解锁奖励），Boss 的个性化机制通过低耦合接口注入，不侵入通关流程。

### 13.2 Boss 基础接口（GDScript）

```gdscript
class_name BossBase extends Node

# 引擎调用——通关流程钩子
func get_name() -> String: pass
func get_intro_dialogue() -> Array[String]: pass  # 入场台词
func get_phase_count() -> int: return 1           # 几阶段

# 每阶段开始时引擎调用，Boss可改变规则
func on_phase_start(phase: int) -> void: pass

# 玩家答对/答错时引擎回调，Boss可触发特殊反应
func on_player_correct(attack_type: String, combo: int) -> void: pass
func on_player_wrong(attack_type: String) -> void: pass

# Boss 自身回合（引擎每回合结束后调用）
func boss_action(battle_state: BattleState) -> BossAction: pass

# 死亡台词 / 剧情交代
func get_defeat_dialogue() -> Array[String]: pass
```

### 13.3 特殊机制示例

每个 Boss 子类在上述钩子中实现独立逻辑：

| Boss | 独特机制 |
|------|---------|
| 遗忘图书管理员 | 阶段2封印一种攻击类型，玩家必须用其他类型绕过 |
| 混沌抄写员 | 每回合随机打乱选项顺序，干扰作答 |
| 时间囚徒 | 答题时限随每轮缩短，压迫感递增 |
| 遗忘之主（最终Boss） | 三阶段，每阶段封印一种攻击，同时考察全部知识类型 |
